# 一句话收集：存档、笔记、行动

用户在手机上分享一篇文章并说一句话（例：「留存这篇，记下我认同的观点，周末试一下」），
你把这一句话拆成最多三类创建动作，一次交付，不要求用户挨个 app 操作。

## 工具前置

所有外部操作经 `minis-mcp-cli`（shell_execute）完成：

| 动作 | server | 工具 |
|---|---|---|
| 存档（网页证据） | pagevault | capture_url / search_archives |
| 笔记（观点） | memos | 以 `minis-mcp-cli tools memos` 实际列表为准（创建、搜索两类语义） |
| 任务（行动） | larry-todo | add_todo / list_todos |

memos 未注册或不可达时降级：只做存档与任务，并在回报里说明「memos 未接入，笔记没记」。
不要因此中断另外两类动作。

## 流程

### 1. 拆解与计划

把用户的话拆成动作清单，在回复里**先展示将创建什么**，每项一行：

- 存档：〈标题或 URL〉 → PageVault
- 笔记：〈观点草稿，引用用户原话〉 → Memos
- 任务：〈做什么〉，截止〈时间〉或「未定」 → LarryTodo

用户没说的不要编造：观点只写用户认同的那句原话；任务没有时间就标「未定」，
不要默认「今天」。

**追问规则**：信息缺口一次问全，只问影响创建的（例：「记下观点」但没说是哪篇哪段、
「周末试一下」但没说试什么）。不问装饰性问题（优先级、标签）。用户原话已完整时，
展示计划后直接执行，不等二次确认。

### 2. 查重（重试不重复创建的关键）

执行前先查，命中即复用，不重复创建：

- 存档：`pagevault search_archives`（query 用标题关键词或域名），已入库则跳过 capture，
  直接引用已有存档 id。
- 笔记：memos 搜索同类关键词，内容实质相同（同观点同文章）则跳过并说明。
- 任务：`larry-todo list_todos`，同标题未完成则跳过；同主题但信息更全时更新旧任务
  而不是新建（update_todo 会全量清空未传字段，传参要带全）。

`capture_url` 较慢（10-60 秒）属预期，不要中途放弃重试；如果确已失败，
重试前必须再 `search_archives` 确认没有半成品入库。

### 3. 执行

三类动作相互独立，一个失败不阻断其他两个。失败的那项回报原因
（服务不可达 / token 失效 / URL 抓不到），成功的照常交付。

### 4. 回报

每项给关联链接或 id，全失败的项单独列出：

- 存档：存档 id + 原文 URL
- 笔记：memos 链接或 id
- 任务：recordId + 截止时间

最后一句话收尾，不重复罗列。

## 边界

- 不主动 `read_archive full=true` 把存档全文发给模型：原文读取是单独授权的操作，
  用户要求「读一下这篇再记」时才读。
- capture 失败且 URL 需要登录态时，说明「这篇要在 PageVault app 里手动存」，不要反复重试。
